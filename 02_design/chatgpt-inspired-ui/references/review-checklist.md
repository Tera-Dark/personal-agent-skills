# ChatGPT-inspired Functional UI · 审查清单

## A. 首屏的五秒测试
- [ ] 首次打开便知道当前页面要完成什么。
- [ ] 有且只有一个主视觉任务或主要动作；次要操作不会压过它。
- [ ] 首屏有明确的主区域，而非大量同等权重的卡片。
- [ ] 用户能找得到导航、当前状态和返回路径。
- [ ] 删除装饰后，内容结构仍然清楚。

## B. 典型失败模式 → 修改

| 症状 | 影响 | 修复策略 |
| --- | --- | --- |
| 大量嵌套卡片/阴影 | 信息零散、显得臃肿 | 移除非必要容器，用间距/细分隔线分组 |
| 每个区域彩色 badge | 注意力分散 | 仅保留实际状态与告警色 |
| 侧栏菜单太密/全图标化 | 难找功能 | 按用户工作流重组，关键入口附文字 |
| 主内容被工具栏挤压 | 完成任务变慢 | 稳定工作区，将低频设置收进 Inspector |
| 移动端照搬桌面三栏 | 可用区域不足 | 单任务流、抽屉导航、按需展开检查器 |
| 输入区只有 placeholder | 容易迷失、无障碍差 | 永久标签 + 可见说明/错误 |
| 仅 hover 才可操作 | 触屏/键盘失败 | 点击与 focus 状态也可访问 |
| 一直旋转、不显示进度 | 不知道是否卡死 | skeleton/状态/取消或重试 |
| 文本灰得读不清 | 可读性失败 | 按实际配对测 WCAG AA |
| 保存不提示成功失败 | 用户反复操作 | 操作后给可理解的状态反馈 |
| 没有空态 | 新用户不知从何开始 | 解释下一步、提供真实行动入口 |
| 所有布局固定 px 宽高 | 缩放及手机溢出 | 弹性列、容器约束、内容驱动断点 |
| 所有产品完全一个样 | 场景辨识度差 | 保留独立导航和小范围品牌表达 |
| UI 看似 ChatGPT 官方 | 混淆产品来源 | 使用原创命名、图标、Logo、文案 |

## C. 验收矩阵

分别记录 PASS / FAIL / NOT TESTED（不可把 NOT TESTED 写成 PASS）：

1. **宽度**：360 / 390 / 768 / 1280px；包含长标题、长列表与超宽数据。
2. **输入**：键盘 Tab/Shift+Tab、Enter/Space、Esc、焦点环、屏幕阅读器标签。
3. **状态**：首次使用、无数据、加载中、网络错误、验证错误、成功确认、无权限。
4. **主题**：浅色、深色、系统切换、200% 缩放；实际文字配色与识别控件、状态、焦点所需的非文本对比，不能以装饰性浅分隔线充当唯一边界。
5. **触控**：手指点击误触、滚动、输入法唤起、safe-area、触控与 hover 不一致。
6. **性能**：首屏资源、长列表、重复渲染、动画运动偏好；只陈述真实测量结果。
7. **回归**：原有功能、保存/导出/导入、导航路由、键盘快捷键、状态持久化。
8. **视觉与参考**：分别实看应用主任务或官网首屏、内容节奏、标题层级、空白和移动端布局；有参考时核对观察到的结构而非声称像素级一致。不能运行或未看参考则标 NOT TESTED。

## E. 实例化启发（不是强制模板）

- 任务清单：左侧导航、中央可扫描列表、右侧可选详情；手机改全屏列表 + 详情页。
- 像素工作台：最大化画布与时间轴，属性设置浮层/抽屉；工具选中和键盘操作要清楚。
- 小型生成器：选择项→结果→复制三步足够时不要加数据分析页。
- 长文阅读：安静的阅读柱、目录与字体设置按需显现，不要增加无用统计卡片。
