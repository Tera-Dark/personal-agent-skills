# v2.1.0 · 从"skill 仓库"到"一个链接就能跑的 harness"

> 前置：`docs/reviews/2026-09-27-v2.0-review.md`（品味层与结构合并）。
> 本次目标（owner 原话）：给 GPT / Gemini 这类有视觉能力的对话模型用；后续通过聊天不断加杂七杂八的功能；根基打牢，做成 harness 级别的基座；**直接甩一个 GitHub 链接就能正常运作**。

---

## 1. 目标改变了什么

v2.0 的前提是"运行时会自动发现 `SKILL.md`"（Claude Code / Codex 那种）。ChatGPT 和 Gemini 没有这个机制：给它一个 URL，它抓回来的是**一个文档**。所以分发单位必须是**单个编译好的文件**，而"怎么工作"必须写进那个文件里，而不是靠运行时。

由此推出四件必须有的东西：

| 需要 | 实现 |
|---|---|
| 一个文件说清"你现在是谁、每轮怎么做、什么时候去拿什么" | `kernel/KERNEL.md` |
| 一次抓取拿到全部必需内容，其余按需再抓一次 | `scripts/build.py` → `bundle/HARNESS.md`（kernel + 索引 + always-on 模块）+ `bundle/modules/<name>.md`（每模块一个文件） |
| 仓库首页就是入口，模型看到的第一句话就是指令 | `README.md` 顶部的 AI 引导块（抓 HARNESS.md、按它工作、不许总结、抓不到时的固定回复） |
| owner 在聊天里加模块后不需要本地工具链 | `.github/workflows/harness.yml`：push 到 main → 校验 → 重建 → 自动提交 bundle |

## 2. Kernel 里对"驾驭 LLM"真正起作用的几处

- **握手行是版本探针**：`Harness v2.1.0 loaded · 14 modules · …`。owner 一眼知道加载的是哪个版本、索引是否完整。它同时是反总结机制——模型的第一句话被固定了。
- **两级加载 + 卡片降级**：抓不到模块时不是失败，而是按索引里的卡片（模块契约）工作并标 `[card-only]`。ChatGPT 每轮抓取有限，这个降级路径会经常被用到。
- **Session State**：≤12 行的状态块（目标模型、模式、锁定事实、已认可维度、已否决项、prompt 版本、已加载模块）。迭代式提示词工作里模型最常见的失败是第三轮忘了第一轮锁定的东西；状态块把它变成可见、可查（`/state`）的对象。
- **视觉协议**：`seen:` 先行，观察与推断分开标。owner 用的是有视觉能力的模型，参考图和生成结果都会进来；不让模型描述看不见的细节是防幻觉的第一道闸。
- **证据标签成为 kernel 级规则**：v2.0 里只有 Anima 档案在用 Official / Community / Personal experiment 分级。现在任何关于任何图像模型行为的断言都必须带标签，`[Unverified]` 是合法答案。这是对"GPT 会很自信地编 NAI5 参数"的直接防御。
- **扩展协议**："加一个 X 功能" → 查重 → 选层 → 按模板输出**完整文件 + 精确路径** → 告诉 owner 提交两步。模板里凡是会被校验的东西都写成了注释提示。已实测：用模板生成一个 `06_extensions/tweet-caption-writer` 直接通过校验并进入索引（15 modules）。

## 3. 按 owner 授权自主决定的事

| 事项 | 决定 | 理由 |
|---|---|---|
| `04_tools/` 三个占位 | 保留，状态改 `planned`；索引里可见但不可加载，遇到时答 `[no module]` 并提议 `/new-module` | 它们记录了意图，在 bundle 里几乎不占 token；删了 owner 还得重新想 |
| 品味签名那句话 | 保留 | 它是从证据归纳的，且所有文件只引用它——owner 改一处即可 |
| 六组对照示例 | 保留并放进 always-on | 它们是 23k 里最值钱的 8k；品味靠示例传递，不靠规则 |
| kernel 语言 | 英文；品味与创作模块中文；回复跟随 owner；prompt 永远英文 | 跨模型指令精度；owner 思考品味用中文 |
| 通用模型适配器 | 新建 `general-image-prompt-adapter`，只写结构与证据标签，不写未核实的模型参数 | v2.0 的 router 有 "General Image Models" 一条但没有落点；owner 用 GPT/Gemini 生成 prompt，目标不会只有 Anima 和 NAI5 |
| always-on 集合 | identity（签名、否决、语气）+ director（动作、诊断、示例）+ router + evaluation ≈ 23k tokens | 40k 预算内；这是"人味"的全部来源，不能按需 |
| 生成物入库 | `bundle/` 和 `docs/skill-registry.md` 提交进仓库 | 必须能被 raw URL 抓到；CI 保证它不过期 |
| 上一版 REVIEW.md | 移到 `docs/reviews/` | 根目录只放入口和配置 |

## 4. 验证

```
python3 scripts/validate_skills.py            OK — 0 errors, 0 warnings（14 skills）
python3 scripts/build.py                      core ≈22.9k tokens · full ≈56k tokens
python3 scripts/validate_skills.py --check-bundle   OK
负向测试：错误命名 / 错层 / 缺字段 / 引用不存在 / 层外 skill → 6 errors, exit 1
正向测试：模板生成的扩展模块 → 通过校验、进索引、生成 bundle 文件
```

未能在沙箱内验证的：GitHub Actions 实际运行（需要推送）；ChatGPT / Gemini 实际抓取行为（需要仓库公开可达）。两者的排查表在 `docs/usage.md § 5`。

## 5. Owner 推送后要做的三件事

1. 合并到 `main`，等 Actions 绿（首次会因为 `paths-ignore` 不触发重建——bundle 已随本次提交入库，不需要）。
2. 新开 ChatGPT / Gemini 会话，只发仓库链接，确认握手行是 `Harness v2.1.0 loaded · 14 modules · 说需求，或发参考图。`
3. 跑 `tests/test-suite.md § 3 Design-01`（设计一个有创意的原创女性角色）：输出里应有带动词的命题、否决的方向、删掉的东西、一处怪。缺三项以上 → 回它"走 director"，并把这一轮记下来——那是 kernel 需要再收紧的地方。
