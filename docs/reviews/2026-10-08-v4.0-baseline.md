## Baseline ownership concerns

1. Anima and NAI5 duplicate large portions of visual prompt planning.
2. Several Anima stages are model-agnostic concerns currently implemented as Anima-only modules.
3. User taste/calibration knowledge is repeated across identity, director, character, illustration, and NAI5 modules.
4. Router and Kernel duplicate pipeline-internal details.
5. NAI5 artist policy exists in more than one source and requires a single owner.
6. Evaluation is globally embedded although it is primarily feedback-path functionality.

## v4.0 target

- One shared Visual Prompt Core.
- One shared Danbooru verification boundary.
- Two thin terminal renderers: Anima and NAI5.
- Design ownership remains in director/specialists.
- Renderer ownership is limited to target-model syntax.
- Every piece of persistent user taste has one owner.
- Preserve Web-first execution and fail-closed behavior.
- Preserve all existing high-value Anima/NAI5 regressions while reducing runtime context.
