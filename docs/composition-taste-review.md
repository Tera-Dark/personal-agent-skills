# 构图审美：审查结论与实测

目标：让用户点名的审美真正影响画面构图，减少模板式主体、装饰与叙事。它是创作机制改进，不保证每次生成画面更好。

## 找到的断点

1. 原 L2 轻量任务卡可能在点名「小画师脑」时先命中，却未明确要求读取对应资料；模型容易只复述审美名称。现在普通小画师请求使用轻量构图卡，明确要求完整模块或需要深入时仍读取完整模块和参考。
2. 原规则在「不强制怪点」与「必须有刺点、物件、叙事或物理主光」之间冲突；部分表格把正面、静止和对称直接当负例，容易制造另一套公式。
3. 上游做了构图判断后，提示词压缩仍可能只留下风格形容词，丢掉主体占幅、留白、裁切和焦点关系。
4. 当前审美基准仍是 IMAGE-PENDING；静态测试能检查加载与规则，不代表真实成图符合用户审美。

## 本轮采用的方法和边界

- [Anthropic canvas-design](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)：借鉴用形、空间、色彩和层次表达，而非堆文字；不照搬其长篇设计宣言或强制抽象展览风。
- [art-direct](https://github.com/nraford7/art-direct/blob/master/SKILL.md)：借鉴比较结构不同的视觉方向并写明取舍；日常单会话默认在内部快速比较，不要求用户每次选方案。
- [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)：借鉴识别模板默认值的思路；不把网页排版规则生搬进插画，也不禁止用户喜欢的居中或对称。

这是对公开方法的独立概括，不导入第三方 skill 文本。项目自己的身份、原作设定、当前需求和用户反馈始终优先。

## 网页会话测试：先测加载，再测图

在新对话贴仓库链接，分别使用：

1. 「用小画师审美做 NAI5 白底半身，保留原服，安静不加道具。」检查实际读取轻量构图卡，包含可画的裁切/留白关系；不得冒称读取完整模块。
2. 「读取完整小画师脑及相关审美，用 NAI5 设计白底半身肖像，只输出提示词。」检查实际读取完整模块与所需参考；读取失败时不能伪称已读取。
3. 「同一角色与服装，做居中正面、对称而克制的肖像。」检查没有擅自改成偏置、动态、添花或加剧情。
4. 「上一张构图保留，只改表情。」检查 FAST VARIANT 不借读取审美之名重做画幅、服装或构图。
5. 「这个构图很 AI，人物像贴在背景上。」检查先定位用户指出的构图问题，而非加光、粒子或自动补剧情。
6. 提供图并说明「方案不错，但生成的手坏了」：优先处理技术问题并锁定构图；只给文字时，不能声称看过图或断言故障原因。

需要看加载过程时可另问「本轮读了哪些文件、具体采用了哪些构图判断」；PROMPT ONLY 模式仍只给提示词。若链接不可读，让模型说明；不要将记忆冒充已读取。

再用真实模型做 A/B：固定角色、服装、目标模型、画幅和生成设置，旧版与新版提示词只改变一个明确构图维度；多个配对 seed，保留失败样本。由用户比较第一眼构图、主体与空间关系、情绪、身份保真，并记录偏好或平局。对不同 prompt 相同 seed 不能视作严格因果保证；没跑图就标 IMAGE-PENDING。不要把私图或完整聊天默认提交到公开仓库。已有记录格式见 [visual benchmarks](../tests/visual-benchmarks/README.md)。
